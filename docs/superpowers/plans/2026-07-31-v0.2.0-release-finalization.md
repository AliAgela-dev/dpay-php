# v0.2.0 Release Finalization (Plan 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the finished-but-unreleased work on
`feat/dpay-spec-alignment-v0.2.0` into a tagged `v0.2.0` release — roll the
CHANGELOG, make `UPGRADING.md` release-shaped and discoverable, get CI to
actually run this branch, and tag it.

**Scope decision (2026-07-31):** Plan 4 (merchant reads / invoices —
`AccountClient`, `PaymentsClient`, `PayMethodsClient`, `InvoicesClient` and
their DTOs) remains unbuilt and is **explicitly excluded**. It slips to
`v0.3.0`. Three of its four clients can't be live-verified against the
sandbox today (`/auth/me`, `/payments`, `/invoices` are unrouted there), so
holding the release for it buys nothing. The one ⚠️ row in `CLAUDE.md`'s
spec-alignment table (per-gateway limits) stays open and is
**accurately documented as open** — that is the intended end state of this
plan, not an oversight.

**Also excluded, deliberately:** the logo path mismatch (needs a product
decision — see "Requires your action" at the end), and the three live
verification gaps (Moamalat LightBox, webhook end-to-end delivery,
Idempotency-Key replay). None of them are code defects this plan can fix.

**Why this matters:** four phases of work — 36 changed `src/` files, 191
tests — are sitting on a local branch that has never been pushed. CI has
therefore never run it on PHP 8.2 or 8.3, which is success criterion #8 of
the original design. A new `UPGRADING.md` exists that **nothing links to**.

**Architecture:** Docs and release mechanics only. No `src/` changes, no new
tests, no behavior change. Every task is one file plus a commit. The final
tasks are gated on explicit user approval because they are outward-facing.

**Tech Stack:** Markdown, git, `gh` CLI, Composer scripts (PHPUnit + PHPStan).
